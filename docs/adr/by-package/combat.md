# ADRs governing combat

Generated by `pnpm adr:index`. Compact reference combining
repository-wide rules and package-specific rules. Does not replace
the canonical by-scope pages; open an ADR for context and exact
boundaries.

## Repository-wide (apply here too)

- [ADR-0347](../ADR-0347-repository-authority-and-rebaselining.md) Artifacts that never existed in reachable history are unverified legacy references; never recreate them from their filenames.
- [ADR-0351](../ADR-0351-canonical-values-units-fixed-point.md) All authoritative values are stored as canonical fixed-precision types using a single rounding vocabulary; units, currency, and locale convert only at the presentation boundary.
- [ADR-0361](../ADR-0361-deprecate-yaml-outside-internationalization.md) YAML is reserved for internationalization catalogues and mandated infrastructure; all other authored content is declarative TypeScript under constrained domain constructors.
- [ADR-0364](../ADR-0364-worktree-and-git-workflow.md) At most five worktrees including the main checkout; each on its own short-lived branch cut from `dev`; manage through `pnpm worktrees` which uses a locked JSON registry under the Git common directory; merge into `dev` locally after gates are green; one session per checkout.
- [ADR-0365](../ADR-0365-verification-gates-and-infrastructure.md) Verification gates enforce golden-repin discipline, reachability, toolchain integrity and agent scoped checks under `pnpm heavy` serialisation; pipeline artifacts are GitHub Issues; unreachable combat modules stay dormant.
- [ADR-0366](../ADR-0366-adr-code-and-replay-practices.md) Every current ADR states its rule and scope and supersedes acyclically; code carries no comments; the determinism baseline is an approval-gated replay corpus; debug screens stay internal.

## combat-specific

- [ADR-0340](../ADR-0340-combat-classification-and-research-technology-alignment.md) The combat ship-type classifier, catalogue technology ids and research screen projection each align engine or UI behaviour to authored scenario content without changing save or wire formats.
- [ADR-0345](../ADR-0345-ship-design-model-and-draft-schema.md) The ship design data model defines a versioned draft with optional fields, a canonical armour-region set mapped to the manual's nine universal fields, named armour schemes as deterministic transformations, and additive options from balance targets, all guarded by a session that explains new blocking or critical findings at once.
- [ADR-0346](../ADR-0346-ship-component-catalogue-and-capability-model.md) The ship-component catalogue is organised by family and nation with per-record provenance, defines part families and capability kinds for all equipment eras, carries sourced or BALANCE_TARGET values, and consumes part capabilities through explicit ruleset sections.
- [ADR-0357](../ADR-0357-training-exercises-division-growth-and-explanation-trees.md) Division cohesion and experience grow through pure rules; special training is a nation program with proficiency tracked in funded months; exercises are commanded for the following month through the assignment slot and cost doubled active maintenance; training effects reach battle through one per-side effects record; displayed numbers carry explanation trees built from the same calculation the engine uses.
- [ADR-0358](../ADR-0358-combat-engine-architecture.md) `@bluewave/combat` exports exactly `resolve`, `advance`, `generate` and the root contract; all subsystems, orders, realism and combat modules are subpath seams.
